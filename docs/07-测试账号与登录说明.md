## 登录入口

| 使用端 | 本机默认地址 | 说明 |
|---|---|---|
| 学生端 H5 | http://localhost:5173/login | 选择「学生点单」，手机浏览器也可使用 |
| 学生端 Web | http://localhost:5174/login | 桌面浏览器使用 |
| 配送员端 | http://localhost:5173/login?mode=rider | 选择「配送员登录」 |
| 商家 / 平台控制台 | http://localhost:5175/login | 共用入口，登录后按账号角色进入对应页面 |

`localhost` 只指当前设备。其他电脑或手机测试时，请使用环境维护者提供的实际地址；不要在手机上直接使用上述 `localhost` 地址，也不要自行开放数据库或公网端口。

## 学生账号

H5 和 Web 共用学生账号与密码，在「学号」输入框填写账号。

| 学号 / 账号 | 密码 | 身份 | 建议用途 |
|---|---|---|---|
| `2022010101` | `010101` | 张狗蛋，已认证学生 | 浏览菜单、购物车、下单、查看个人订单 |
| `2022010102` | `010102` | 李鹿，已认证学生 | 第二位学生，检查购物车与订单隔离 |
| `admin` | `admin` | 学生端演示账号 | 快速体验学生端，不具备平台管理权限 |

两个数字学号的初始密码是学号后 6 位，**开头的 `0` 必须保留**。该规则只适用于这两个种子账号，不适用于用户自行注册的账号。

学生 `admin` 由 V3 迁移创建。虽然名称是 `admin`，登录学生端后仍是学生身份。

## 商家与平台账号

默认开发环境中，下列控制台账号密码均为 `demo123456`。

| 账号 | 密码 | 角色 | 所属档口 / 范围 |
|---|---|---|---|
| `chuanxiang` | `demo123456` | 商家负责人 | 川香盖浇饭，档口 ID `1` |
| `chuanxiang02` | `demo123456` | 商家店员 | 川香盖浇饭，档口 ID `1` |
| `lanzhou` | `demo123456` | 商家负责人 | 兰州牛肉面，档口 ID `2` |
| `jido` | `demo123456` | 商家负责人 | 悸动奶茶，档口 ID `3` |
| `admin` | `demo123456` | 平台管理员 | 平台管理，不是学生账号 |
| `merchant4` | `demo123456` | 商家负责人 | 黄焖鸡米饭，档口 ID `4` |
| `merchant9001`–`merchant9026` | `demo123456` | 商家负责人 | 样本档口，账号尾部即档口 ID，例如 `merchant9020` 对应川湘木桶饭 |

样本档口账号由 `pnpm run import:sample` 自动补齐；已导入样本但未生成账号的库可执行 `pnpm run ensure:accounts`。档口账号仍按商家归属隔离，学生把订单下到哪个档口，就要用该档口的账号登录控制台接单。

- 商家负责人可管理本店业务，退款审核仅允许本店负责人操作。
- 商家店员可查看本店数据，以及接单、开始制作、出餐、核销和拒单；不能修改菜单、营业设置或审核退款。
- 平台管理员使用平台管理功能，不代替商家负责人审核退款。
- 学生与控制台是两套账号体系。**学生端 `admin / admin`，控制台 `admin / demo123456`，不能混用。**

控制台统一密码由 [application-dev.yml](../server/src/main/resources/application-dev.yml) 的 `smartorder.security.dev-account-password` 决定，仅对仍使用开发占位哈希的账号生效。若环境覆盖了该值或账号已设置独立密码，以环境实际配置为准。

## 配送员账号

| 学号 | 密码 | 姓名 | 登录方式 |
|---|---|---|---|
| `2022010101` | `010101` | 张狗蛋 | H5 登录页选择「配送员登录」 |

配送员复用学生账号密码，但必须具备已启用的配送资格。当前种子数据包含此账号的演示配送资格；V4 迁移也会在对应种子学生仍满足条件时补入资格。旧环境需要部署包含配送功能的后端并完成迁移。

学生端演示账号 `admin` 和学生 `2022010102` 默认没有配送资格，不能因为能登录学生端就认为能进入配送工作台。
