## 二、实现质量观察

### 做得好的
1. **零后端改动** — 完整消费现有 favorites/reviews endpoint，没有去改后端 summary 加 isFavorited 字段
2. **Pinia store 设计合理** — setup 风格 + Set 类型 + watch tokenStore.profile 自动 load/clear；乐观更新 + API 全量刷新模式
3. **避免 button 嵌套** — DishCard 把 dish__media 从 `<button>` 改成 `<div role="button">`，这是正确做法
4. **类型正确** — 实现过程中发现 ReviewDto.ratingScore 是 1-5（非 0-100）后及时调整，typecheck 零错误
5. **stopPropagation 全覆盖** — router-link / article @click 场景都正确加了 `.stop`
6. **可访问性** — `aria-label="收藏"` / `"取消收藏"` 加了
7. **两端并行开发 + HMR 即时生效** — 没有重新启动任何服务（符合用户要求）

### 可改进（非阻塞）
1. **Web fav 按钮 fill 红心** — 用 `:deep(svg path) { fill: currentColor !important }` 覆盖 AppIcon 的 `fill="none"`，如果以后 AppIcon 内部结构改了可能需要同步维护。可以考虑让 AppIcon 本身支持 is-filled prop。
2. **FavoritesView.vue 还在直接调 `favoritesApi.list()`** — 应该切到 `useFavoritesStore()` 复用同一份 store，避免页面间收藏状态不一致。这是后续优化项，不阻塞本次验收。
3. **评论列表页未实现分页** — 当前后端 `reviewsApi.byMerchant` 返回全部评论，当评论很多时会有性能问题。spec 里没要求，本次不算。
